# 게임 화면 색약 점검

## 요약
"색약에게도 잘 보이나?"는 눈으로 짐작하지 않고 **스크린숏을 시뮬레이션 행렬로 돌려 본다.** 볼 것은 다섯 가지다.
- 원본
- 1형(protan)
- 2형(deutan)
- 3형(tritan)
- 흑백(휘도)

위험·거절·적의 공격 예고 같은 **알아야 하는 것**이 다섯 보기 모두에서 남아야 한다. 남지 않으면 색을 더 진하게 하지 않는다. **밝기 차와 모양**을 더한다.

## 본문
### 방법
1. 확인할 장면을 스크린숏으로 찍는다. 헤드리스 브라우저라면 한 장면을 여러 번 찍는다. 깜빡이는 표시는 프레임마다 다르다.
2. sRGB → 선형 RGB로 바꾸고, 3×3 행렬을 곱한 뒤 다시 sRGB로 바꾼다.
3. 흑백은 선형 RGB의 Rec.709 휘도(0.2126 R + 0.7152 G + 0.0722 B)를 쓴다.
4. 잘라서 다섯 칸을 나란히 놓고, 정수 배율로 키워 본다(도트는 최근접).

정도 1.0 행렬(Machado 2009, 선형 RGB, 행 = 출력 R·G·B):

| 형 | 행렬 |
|---|---|
| 1형(protan) | [0.152286, 1.052583, −0.204868] / [0.114503, 0.786281, 0.099216] / [−0.003882, −0.048116, 1.051998] |
| 2형(deutan) | [0.367322, 0.860646, −0.227968] / [0.280085, 0.672501, 0.047413] / [−0.011820, 0.042940, 0.968881] |
| 3형(tritan) | [1.255528, −0.076749, −0.178779] / [−0.078411, 0.930809, 0.147602] / [0.004733, 0.691367, 0.303900] |

### 한 번 해 본 결과(탑다운 도트 게임, 0150)
| 무엇 | 원본 | 1·2형·흑백에서 | 고친 것 |
|---|---|---|---|
| 붉은 가시 덤불(바닥 위험) | 초록 풀 위 빨강 | 어두운 덩어리만 남아 바위처럼 보임 | 몸은 어둡게, **가시는 거의 흰색**: 밝기 차로 "뾰족함"이 읽힌다 |
| "안 됨" 붉은 테두리(HUD) | 빨강 | 고른 칸의 **금빛 테두리와 같은 색**이 됨 | 흰색·빨강 번갈아 깜빡이기 + **✕ 모양** |
| 적 공격 예고 테두리(붉은 띠·점선) | 옅은 빨강 | 어두운 바닥에 묻힘 | 테두리를 밝은 산호색으로, 진하기 하한을 올림(채움은 그대로 옅게) |
| 떨어질 돌 자리(붉은 고리 + 커지는 그림자) | 보임 | 고리가 옅지만 **그림자가 커지는 것**이 남음 | 그대로 |

## 왜?
- 빨강·초록은 1·2형에서 같은 노랑·올리브 쪽으로 모인다. 그래서 빨강을 아무리 진하게 해도 초록 위에서는 구별이 안 된다. 다섯 보기에서 남는 것은 **밝기**뿐이다.
- 흑백 점검(KB 도트 아트 안내)은 밝기 차만 본다. 다만 "두 색이 같은 색이 된다"는 흑백만으로는 안 보인다(빨강 테두리 ↔ 금빛 테두리). 시뮬레이션이 그것을 잡는다.

## 함정
- 감마 sRGB 값에 바로 곱하면 결과가 틀어진다. 선형으로 바꾼 뒤 곱한다.
- 모양을 더해도 크기가 1px이면 폰 화면에서 안 보인다. ✕는 테두리를 두르고 대각선 7~9px로 그린다.
- 시뮬레이션은 정도 1(가장 심한 경우)이다. 이상 삼색형(더 흔하다)은 그 사이다. 정도 1에서 남으면 대개 남는다는 추론이고, 확인한 것은 아니다.
- 소리·떨림 같은 색이 아닌 신호를 이미 줬다고 끝이 아니다. 화면만 보는 순간(소리 끔)에도 남아야 한다.
