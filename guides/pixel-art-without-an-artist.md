# 그림 못 그려도 도트 게임 만들기

## 요약
에셋 팩 **하나를 메인으로 정하고 세계를 거기 맞춘다.** 해상도(16×16 등)와 팔레트를 통일하고, 부족한 건 그리기가 아니라 "손보기"(팔레트 교체, 반전, 합성)로 채운다. 라이선스는 팩마다 다르니 받을 때마다 확인한다.

## 절차

1. **해상도와 내부 화면을 먼저 정한다.** 타일 16×16, 내부 해상도 320×180이면 팩도 16×16 기준으로만 본다. 32×32 팩을 섞으면 선 두께가 달라 바로 티가 난다. → [픽셀 퍼펙트 렌더링](../reference/macroquad/pixel-perfect-rendering.md)
2. **메인 팩을 고른다. 기준은 "주인공 애니메이션 종류".** 대기·이동·공격·회피·피격·사망이 있는 캐릭터 팩이 먼저다. 전투감의 절반은 애니메이션 타이밍이라 프레임이 부족한 주인공은 나중에 반드시 발목을 잡는다. 타일셋·적·UI는 그 팩 작가의 다른 팩이나 같은 팔레트 계열에서 보충한다.
3. **라이선스를 읽는다.** 자주 보이는 종류:
   - CC0: 제한 없음. 출처 표기 불필요.
   - CC-BY: 상용 가능, 출처 표기 필수(크레딧 화면에 적는다).
   - CC-BY-NC: 비상용만. 판매·광고 수익이 있으면 쓸 수 없다.
   - 작가 고유 라이선스: "게임에 포함 가능, 에셋 재배포 금지"가 보통이다. 레포를 공개할 거면 **에셋을 공개 레포에 넣어도 되는지**가 별도 질문이다.
   확인한 내용은 레포의 `assets/LICENSES.md`에 팩 이름·작가·URL·라이선스·받은 날짜로 기록한다.
4. **손보기 도구는 Aseprite 하나로 충분하다.** 그림 실력 없이 되는 것: 팔레트 교체(적 바리에이션은 색만 바꿔도 된다), 좌우 반전, 두 스프라이트 합성(몸 + 장비), 프레임 복제·타이밍 조절, 이펙트는 단색 도형 몇 프레임.
5. **공개 레포라면 에셋은 분리한다.** 재배포 불가 팩은 `.gitignore` 하거나 private 서브모듈/릴리스 첨부로 두고, 레포에는 `assets/README.md`에 "어디서 받아 어디에 두는지"를 적는다.

## 함정
- 팩 여러 개를 섞으면 해상도가 같아도 **팔레트와 외곽선 스타일**(검은 외곽선 유무, 선 두께)이 달라 어색하다. 섞어야 하면 팔레트를 메인 팩 것으로 재매핑한다.
- 캐릭터 후보(해금 캐릭터 등)는 세계관으로 먼저 정하지 말고 **쓸 수 있는 팩에 그 동물·직업이 있는지**로 먼저 거른다.
- 무료 팩은 작가가 라이선스를 바꾸거나 내릴 수 있다. 받은 시점의 라이선스 파일을 함께 보관한다.

## 공개 레포에서 유료 팩 다루기
- "게임에 넣어 배포는 되지만 에셋 자체의 재배포·재판매는 금지"는 유료 팩의 흔한 조건이다. **공개 GitHub 레포에 원본 PNG를 커밋하면 누구나 원본을 받아 갈 수 있어 재배포로 볼 여지가 크다.** 레포가 공개인지 먼저 확인한다.
- 분리 방법: 팩은 `assets/vendor/`(gitignore)에 두고, CI는 비공개 에셋 레포를 `actions/checkout`(repository·token 입력)으로 같은 경로에 받는다. 시크릿이 없으면 대체 그림으로 빌드되게 해 두면 외부 기여자 PR도 깨지지 않는다.
  ```yaml
  - name: Fetch vendor assets (private repo)
    if: env.ASSETS_REPO != ''          # job env: ASSETS_REPO: ${{ secrets.ASSETS_REPO }}
    uses: actions/checkout@v4
    with: { repository: ${{ secrets.ASSETS_REPO }}, token: ${{ secrets.ASSETS_TOKEN }}, path: assets/vendor }
  ```
  `secrets`는 `if:`에서 직접 못 쓰므로 job `env`로 옮겨 검사한다.
- **비용**: GitHub Free 개인 계정은 비공개 레포가 무제한이다. Actions 분은 **워크플로가 도는 레포** 기준이라, 공개 게임 레포의 워크플로가 비공개 레포를 checkout만 하면 공짜 그대로다. 반대로 게임 레포 자체를 비공개로 돌리면 월 무료 분이 생기고 Release APK도 테스터가 못 받는다.
- **토큰**: fine-grained personal access token, Repository access = 그 에셋 레포 하나, Permissions = Contents 읽기 전용. 만료되면 CI는 팩 없이(대체 그림으로) 빌드되며 멈추지 않는다 → 그림이 갑자기 옛날로 돌아가면 토큰 만료부터 본다. 토큰 화면은 github.com 웹의 Settings → Developer settings에 있다(직접 주소 `github.com/settings/personal-access-tokens/new`).
- **게임이 쓰는 파일만** 비공개 레포에 올린다(우리는 49MB 팩 중 4장, 0.3MB). 노출 범위가 줄고, 빌드가 무엇에 의존하는지 목록이 된다. 라이선스 원문은 그 레포 README에 함께.
- 배포된 웹 빌드 안의 PNG는 누구나 브라우저에서 꺼낼 수 있다. 게임 배포에 원래 따르는 일이고 라이선스가 허락하는 "게임의 일부"다. 막아야 하는 것은 **원본 팩 묶음**의 재배포다.
- "AI 학습 금지" 조항: 팩 이미지를 학습 데이터로 내거나, 생성형 도구(업스케일·스타일 변환·"이 그림처럼" 참조)에 넣지 않는다.
  - AI 어시스턴트가 팩을 **보고 고르고 화면에서 확인하는 것**은 원래 용도(게임 만들기)라 허용으로 정할 수 있다. 다만 그 대화가 학습에 쓰이지 않는 설정인지 먼저 본다(Anthropic 소비자 계정: 학습 설정 끔). 그 대화에 피드백(👍/👎)을 보내면 예외가 될 수 있으니 보내지 않는다(2차, 위 verified).
  - 이 선은 작가가 정한 문장이 아니라 해석이다. 작가 의도가 다르면 작가 뜻을 따른다.

## 직접 찍기: 코드로 그리는 스프라이트
- 문자 격자(한 글자 = 한 픽셀, 글자 = 팔레트 색)로 채움만 적고 **외곽선은 자동**(채운 칸에 4방향으로 닿은 빈 칸)으로 두르면, 부위를 옮겨 동작 프레임을 만들어도 외곽선이 깨지지 않는다. 걷기는 1px 통통 튀기 + 발 이동, 공격은 상체 기울기 + 발 위치, 피격은 눈 모양 교체로 원본에서 파생한다.
- 피격 흰 플래시는 셰이더 없이 **흰 실루엣 줄**을 시트에 함께 만들어 그 칸을 그리면 된다.
- 원본 스크립트를 레포에 두고 PNG는 산출물로 커밋한다. 손으로 PNG를 고치면 다음 생성에서 사라진다.
- **타원을 코드로 쌓아 만든 몸은 안 읽힌다**: 작은 타원 여러 개 + 위치 기반 음영으로 동물을 만들면(2026-10-25 nail-under-the-roots v1) 윤곽이 울퉁불퉁하고 얼룩져 종이 구별되지 않았다. 기본 자세 한 장은 **손으로 격자에 찍고**(큰 덩어리 하나, 3단 음영, 또렷한 2×2 눈), 동작만 코드로 파생하는 편이 같은 수고로 훨씬 낫다. 종 구별은 실루엣으로(귀·꼬리·몸 길이).
- **생성기는 자기 칸 밖으로 찍지 않는다**: 시트 한 칸을 그리는 함수가 `y + 무작위` 같은 식으로 한 줄이라도 넘치면 아래 칸 그림 꼭대기에 그 색이 찍힌다. 게임에서는 "바위 위의 얼룩"처럼 보여 원인 찾기가 어렵다(이음새 묻어남과 헷갈린다). 찍는 함수에서 칸 크기로 잘라 두고, 시트를 만든 뒤 칸 경계 줄이 비었는지 확인한다(직접 겪음, 2026-10-25).
- 도구로 다듬을 때(2026-10, 기억 기반, 가격·라이선스는 각 사이트에서 재확인): **Aseprite**(유료, 소스 공개 EULA, 산출물 상업 사용 가능), **LibreSprite**(Aseprite 옛 버전의 GPL 포크, 무료), **Pixelorama**(MIT, 무료, 웹판 있음). AI 스프라이트 생성기는 산출물 권리·스타일 일관성·팩 라이선스(AI 금지) 문제를 먼저 확인한다.

### 16×16 얼굴을 귀엽게 (그리고 징그럽지 않게)
- **색이 붙으면 한 덩어리로 읽힌다.** 분홍 코 옆에 크림색(발톱)·분홍(손바닥)이 위아래로 붙으면 "벌린 입 + 이빨 + 잇몸"이 된다. 얼굴 둘레 1px은 몸 색이나 빈칸으로 비워 부위를 떼어 놓는다.
- 서 있는 프레임의 무기·발톱은 얼굴과 먼 줄(발 줄)에. 공격 프레임에서만 앞으로 내민다(짧게 보이면 동작으로 읽힌다).
- 귀여움 공식: 큰 눈(2×2 + 하이라이트 1px), 동그란 코(2×2, 아래 한 칸만 어두운 분홍), 눈 아래 볼 홍조 1px, **입은 그리지 않는다**. 이 크기에서 입 한 줄은 대개 찡그림이나 이빨이 된다.
- 쓰러짐은 × 눈(3×3). 검은 2×2로 두면 벌린 입처럼 보인다. 피격은 > 눈.
- 확인은 원본 크기와 8배 확대, **게임 화면(배경 위)** 셋 다. 확대만 보면 괜찮은데 실제 크기에선 덩어리가 합쳐져 보인다.

### 대화창 초상화: "해상도가 높아 보이는" 도트
- **2배 밀도**: 초상화 원본 1px = 게임 픽셀 반(88×88을 44×44 칸에). 화면 배율이 정수면 도트 느낌이 남으면서 표정을 담을 만큼 섬세해진다. 배율이 홀수면 원본 1px을 `floor(배율/2)` 화면 px로 — 반 픽셀은 번져 보인다.
- **코드로 그리기(손 도트 흉내)**: 부위 = 타원, 재질마다 4~5단 색 경사, 빛 방향 하나(왼쪽 위)로 구 음영 → 단 경계만 2×2 바둑판 디더(전체 디더는 지저분하다), 털 뭉치는 반지름을 각도로 물결치게, 짧은 어두운 털 결 몇 가닥.
- **선택 외곽선(sel-out)**: 검은 테두리 대신 닿은 재질의 가장 어두운 색. 빛 받는 쪽은 한 단 밝게. 뒤쪽 가장자리 1px 반사광으로 덩어리가 배경에서 뜬다.
- **눈이 생명**: 큰 흰 반사 + 작은 반사 + 아래쪽 푸른 반사광. 표정은 눈(^ 감은 눈, 눈꺼풀 눌러 결의)·눈썹(안쪽 올림 = 걱정, 내림 = 결의)·입(ω) 세 곳만 바꿔도 충분하다.
- 확인 순서: 원본 3배(전체 구성) → 얼굴만 12배(입·반사 픽셀) → 게임 대화창 안(실제 크기). 같은 어두운 단에 같은 색 입을 그리면 묻힌다 — 입은 별색.
- 16×16 스프라이트와 같은 함정: 얼굴 아래 밝은 면 + 하얀 발톱 줄은 이빨로 읽힌다.
- **"물든(타락한) 아군"을 귀엽게**: 세로로 가는 동공 + 안쪽이 내려간 눈썹은 바로 고양이·악당이 된다(굴토끼 히로인 v1, 2026-10-25). 눈은 둥근 동공·큰 반사·속눈썹으로 두고 **홍채 색**만 바꾼다(졸개와 다른 색 — 특별한 존재 표시). 타락은 털색(채도↓·차갑게), 몸을 감은 덩굴, 눈 밑 그늘로.
- **빠진 초상화가 가장 "덜 만든" 곳이다**: 이름표 옆 색 네모는 대화가 길수록 눈에 띈다. 같은 생성기로 같은 문법(타원 + 단 + sel-out + 큰 반사 눈)을 지키면 새 인물 셋도 한나절이면 채운다. 반쯤 뜬 눈은 "의심"으로 읽힌다 — 다정함은 아래로 휜 감은 눈(︶)으로(직접 확인, 2026-10-25).
- **한 인물의 색 약속은 스프라이트·초상화·일러스트가 같아야 한다**: 물든 = 초록 눈, 돌아옴 = 검은 눈처럼 이야기 규칙이 걸린 색이 매체마다 다르면 규칙이 흐려진다.
- **회복을 그림 하나로**: 몸에 작은 장식(귀 밑동의 꽃)을 달아 타락 = 시들고 빛 바램, 회복 = 핌. 이야기의 변화가 초상화 한 칸 차이로 읽힌다.

### 2배 밀도 한 장 그림의 띠 자국
- 계단 그라디언트(띠)는 1px 디더 없이 깔끔하지만 경계가 선으로 보인다. 1px 바둑판은 홀수 화면 배율에서 1.5배로 늘어 얼룩진다.
- **짝수 좌표에 맞춘 2×2 칸 바둑판**으로 경계 위아래 한 줄씩만 섞는다. 2배 밀도에서 2×2 = 게임 1px이라 홀수 배율(3배)에서도 3×3 화면 px로 고르게 찍힌다(직접 구현, nail-under-the-roots 0049).
- 그라디언트를 그리는 함수 한 곳에 넣으면 모든 그림이 함께 나아진다.

### 무리 속에서 내 캐릭터가 보이게
- 실패의 대부분은 **값(밝기) 실패**다: 같은 갈색·같은 밝기·같은 크기면 실루엣이 달라도 섞인다(두더지 주인공과 흙갈색 들쥐, 2026-10-25 nail-under-the-roots).
- 고치는 순서: ① 적 팔레트를 한쪽으로 기울이기(물든 적 = 보라 쪽 28% + 밝기 82%, 외곽선도 더 어둡고 차갑게) — 종 색은 남는다 ② 주인공은 따뜻하고 밝은 쪽 그대로 ③ **색이 아닌 표시** 하나(발밑 빛 고리, 바닥에 그려 다른 그림을 가리지 않게).
- 확인: 게임 화면을 **흑백**으로 바꿔 주인공이 가장 밝은 덩어리로 남는지. 흑백에서 사라지면 색약 플레이어에게도 사라진다(2차 출처: 게임 아트 가독성 글, Xbox 접근성 가이드라인 102 — 윤곽선·대비, 색만으로 정보를 주지 말 것).
- 참고: [Xbox Accessibility Guideline 102](https://devdocs.xbox.com/gaming/accessibility/xbox-accessibility-guidelines/102), [Readable game art](https://bugnet.io/blog/readable-game-art-why-clarity-beats-detail), [80.lv 실루엣과 대비](https://80.lv/articles/studying-character-art-silhouette-and-contrast)

## 3/4 환경을 "깊이"로 바꾸기
같은 타일에 색조(바닥·벽 따로), 장식표(꽃 → 뿌리·조약돌 → 이끼·빛나는 버섯), 바닥 재질(풀 → 흙), 화면 어둠(플레이어 주변만 밝은 원형 마스크)을 단계별로 입히면 타일 세트를 더 사지 않고도 "내려갈수록 어둡고 음습해지는" 흐름이 나온다. 칸 경계가 보이지 않게 반대 재질 얼룩(가장자리 불규칙, 투명 배경)을 반 칸 어긋나게 덮는다. 빛나는 장식은 어둠을 그린 뒤 한 번 더 그린다.

## 네모 칸 충돌 위에 둥근 지형 그림 굽기
타일 하나씩 찍으면 벽이 직각·띠 모양이라 "네모네모"해 보인다. 충돌은 16px 칸 그대로 두고, **장소가 바뀔 때 지도 전체를 CPU에서 한 장(월드 1px)으로 굽는** 쪽이 오토타일(47칸 blob, 16칸 dual grid)보다 칸 제약 없이 모서리·잡음·그늘을 그린다.
- **모양**: 칸 가운데 값(벽 1, 바닥 0)을 겹선형으로 잇고, 값 잡음(진폭 < 0.5)을 더해 0.5에서 자른다.
  - 곧은 벽은 칸 경계를 따라 물결치고, 모서리는 둥글다.
  - 칸 가운데는 늘 제 칸 쪽이라 그림이 걷는 곳을 가리지 않는다(테스트로 묶기 쉽다).
- **3/4 벼랑**: 1px 열마다 아래에서 위로 훑어, 바닥 바로 위 벽 N px를 앞면(흙 지층·뿌리), 그 위를 윗면(덤불·돌)으로 칠한다. 윗면에서 앞면으로 잎 1~3px를 늘어뜨리면 경계가 산다.
- **바닥**: 큰 값 잡음을 2~3단으로 끊고(경계는 2×2 바둑판), 반대 재질 얼룩은 다른 잡음의 문턱으로. 장식은 칸 해시 × 저주파 밀도로 무리 짓는다(고르게 흩으면 단조롭다).
- **비용**:
  - 1600×960px가 처음 280ms(네이티브)였다. 셋으로 100ms까지 줄였다.
    - 칸마다 둘레 3×3이 같으면 1px 계산 생략.
    - 화면에 안 나오는 깊은 벽은 주기 무늬로.
    - 큰 잡음은 반 해상도.
  - 그래도 브라우저 한 프레임 150ms다. 어두워짐 동안이라 괜찮다고 봤는데, 그 긴 프레임이 밝아짐을 건너뛰게 했다([고정 타임스텝의 함정](../concepts/fixed-timestep-and-hitstop.md#함정)).
  - **나눠 굽기**: 단계(모양 → 벼랑 → 바닥 잡음 → 색 → 장식)와 줄 커서를 둔 굽기 객체가, 한 줄마다 "시간 다 됐나"를 묻고 멈췄다가 다음 프레임에 잇는다. 프레임마다 12ms, 그동안 화면 검정 + 로직 멈춤. 나눠 구운 그림 = 한 번에 구운 그림을 테스트로 묶는다(바이트 비교).
  - 최근 장소 몇 장(텍스처)은 남겨 두면 돌아갈 때 다시 굽지 않는다.
- **바뀌는 칸**(잠긴 문·출구·저장 지점)은 굽지 않고 매 프레임 위에 그린다. 굽기 열쇠에서 바닥으로 세면, 출구가 생겨도 다시 굽지 않는다.
- **방 모양**: 네모 방에 모서리 메우기 + 가장자리 혹 + 바위 무리를 내고, 지켜야 할 칸(문 앞 길·적·상자·출구 자리와 둘레)은 건드리지 않는다. 마지막에 채우기로 이어짐을 보고, 끊기면 네모로 되돌린다. 모양 난수를 굴 배치 난수와 따로 두면 같은 시드 = 같은 굴이 유지된다.

## 한글 UI 폰트 (에셋 팩과 별개의 인프라)
게임 엔진 내장 폰트에는 한글이 없다. 픽셀 게임에 맞는 한글 폰트는 다음 조건으로 고른다: OFL 같은 재배포 허용 라이선스, 픽셀 격자(8·10·12px)에 맞는 윤곽선 TTF, 2,350자 이상.

- **Galmuri** ([quiple/galmuri](https://github.com/quiple/galmuri), OFL 1.1): Galmuri14/11/9/7. README "Legal Stuff"에 따르면 Regular 계열은 일부 글리프(라틴-1, 가나·한자, 일부 기호, 한글 2,355자)가 닌텐도 DS 폰트에서 유래하고, **Galmuri11 Bold·Condensed는 모든 글리프가 제작자의 순수 창작**이다. 걱정 없이 쓰려면 Bold나 Condensed. 320×180이면 Condensed(12px 격자)가 글자 수를 벌어 준다.
- 용량: 원본 TTF는 2.6MB(한글 11,172자). 웹 첫 로딩을 위해 서브셋한다. `pyftsubset`(fonttools)로 KS X 1001 완성형 2,350자 + ASCII + Latin-1(ï 등) + 필요한 기호(▶◀♥♡■□…·)만 남기면 약 450KB.
  ```sh
  pip install fonttools
  python3 -c "print(''.join(chr(c) for c in range(0xAC00,0xD7A4) if (lambda b: b and 0xB0<=b[0]<=0xC8 and 0xA1<=b[1]<=0xFE)(chr(c).encode('cp949','ignore'))), end='')" > ksx1001.txt
  pyftsubset Galmuri11-Condensed.ttf --text-file=ksx1001.txt --unicodes="U+0020-007E,U+00A0-00FF,U+2010-2027,U+2190-2193,U+25A0-25CF,U+2660-2667,U+3131-318E" --output-file=assets/fonts/Galmuri11-Condensed.ttf --name-IDs='*'
  ```
  파이썬 `euc_kr` 코덱은 11,172자를 모두 인코딩하므로(cp949 호환) 2,350자 필터는 EUC-KR 순수 2바이트 영역(B0A1~C8FE)으로 거른다. 서브셋 밖 글자(예: 똠)는 안 나오니 UI 문구를 쓸 때 기억한다.
- 라이선스는 `assets/LICENSES.md`에 파일·출처·라이선스·가공 내용을 표로 남긴다(OFL은 폰트 파일 name 테이블에도 명시돼 있다).
- macroquad에서 찍는 법: [reference/macroquad/pixel-perfect-rendering.md](../reference/macroquad/pixel-perfect-rendering.md) "텍스트" 항목.
