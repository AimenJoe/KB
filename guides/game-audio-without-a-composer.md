# 작곡가·음향 담당 없이 게임 소리 넣기

## 요약
CC0 팩(효과음은 Kenney, 음악은 OpenGameArt의 CC0 곡)에서 고른다. 들을 수 없거나 귀가 지쳤으면 **숫자로 먼저 거른다**(길이·봉우리·RMS·밝기·스테레오 폭·고리 이음매). 고른 파일은 손으로 넣지 말고 **표 + 변환 스크립트**로 만든다(자르기·봉우리 맞추기·고리 이음매 줄이기·모노·크기 맞추기). 코드는 변형을 고르고, 메뉴 소리는 한 곳에서 낸다. 마지막 판정은 사람 귀다.

## 본문
### 1. 출처
- 효과음: Kenney의 오디오 팩(Interface·Impact·RPG). 팩마다 `License.txt`가 들어 있다. **받은 파일 안의 라이선스 글**을 읽고 기록한다(페이지 문구는 바뀔 수 있다).
- 음악: OpenGameArt에서 라이선스를 CC0로 걸러 찾는다. 페이지의 라이선스 칸과 작가 이름을 적는다. 크레딧 의무가 없어도 남긴다. 받은 묶음 안의 readme가 크레딧을 부탁하면 그것도 적는다(법적 의무는 아니어도 지킨다).
- 악기 섞기: 한 게임에 칩튠과 어쿠스틱(피아노·바이올린)을 섞을 때는 **장소의 성격으로 나눈다**(쉬는 곳 = 어쿠스틱, 싸우는 곳 = 칩튠). 장소가 바뀔 때 기분도 바뀌고, 섞임이 실수처럼 들리지 않는다.
- 가족·지인의 연주: 직접 녹음한 곡은 저작권이 연주자에게 있어 라이선스 걱정이 없다. 공개 레포에 넣을지와 크레딧 이름만 먼저 정한다. 휴대폰 녹음도 되고(자동 음량·잡음 제거 끄기, 악기와 50cm~1m, 앞뒤 2초 조용히), 고리용은 30초~1분의 박자 일정한 곡이 이음매 맞추기 쉽다.
- 원본 팩은 커밋하지 않는다(용량). 산출물과 **어디서 받았는지 + 어느 파일에서 만들었는지**만 남긴다(게임의 에셋 라이선스 표).

### 2. 숫자로 고르기(듣기 전에)
| 잴 것 | 어떻게 | 무엇을 거르나 |
|---|---|---|
| 길이·활성 구간 | 봉우리의 1% 넘는 첫·끝 표본 | 메뉴 소리는 60ms 안팎, 타격은 200~300ms, 쓰러짐은 400ms 안팎. 꼬리가 긴 것은 잘라 쓴다 |
| 봉우리·RMS | dBFS | 0dB를 넘으면 정규화 필요, RMS 차이로 크기 균형 짐작 |
| 스펙트럼 무게중심 | FFT 가중 평균 주파수 | 10kHz 넘는 것은 쉿 소리처럼 날카롭다 → 자주 나는 메뉴 소리로는 피한다. 무거운 타격은 200~800Hz |
| 옆/가운데 성분 비 | (L−R)/2 대 (L+R)/2 에너지 | −30dB 아래면 모노로 줄여도 들리는 차이가 없다(파일 절반) |
| 고리 이음매 | 끝 표본과 첫 표본의 차 | 0.1을 넘으면 고리마다 딸깍 → 앞뒤 몇 ms 줄이기 |
- 이름(title_screen, town, dungeon, battle)은 작곡가의 의도라 장소 짝짓기의 첫 기준으로 쓴다. 다만 귀 판정 전까지는 임시다.

### 3. 변환 스크립트(표가 원본)
- 표: (게임 이름, 원본 파일들, 최대 길이). 같은 이름에 파일이 여럿이면 변형이다.
- 효과음: 앞 빈 곳·조용한 꼬리 자르기 → 끝 5ms 줄이기 → 봉우리 −1dBFS → 44.1kHz 모노 16비트 WAV.
- 음악: 모노로 줄이기(폭이 좁으면. 어쿠스틱 곡은 넓어서 스테레오로 둔다) → 앞뒤 5ms 줄이기 → RMS 맞추기(예: −15dB, 봉우리 −1dBFS 안. 스테레오는 가운데(좌우 평균)로 잰다) → 엔진이 푸는 형식으로(macroquad라면 네이티브 ogg + 웹 mp3, [소리(quad-snd)](../reference/macroquad/audio.md)).
- 메타데이터를 지우고(`-map_metadata -1`) 같은 입력이면 같은 출력이 나오게 한다. 다시 돌려도 diff가 없다.

### 4. 코드
- **변형 고르기**: 바로 전 것을 빼고 고른다(무작위만이면 같은 것이 연달아 나온다). 고르는 난수는 게임 로직의 난수와 **따로** 둔다. 소리를 켜고 끄는 것만으로 게임 결과(떨어지는 물건 등)가 바뀌면 안 된다.
- **같은 소리 간격**: 한 틱에 여럿 맞으면 같은 소리가 겹쳐 커진다. 소리(변형 묶음 하나)마다 마지막 시각을 두고 30ms 안이면 건너뛴다.
- **메뉴 소리는 한 곳에서**: 메뉴 장면의 갱신 전후로 "낸 소리 수"를 비교한다. 그 사이에 아무 소리도 나지 않았으면 입력을 따라 하나 낸다(뒤로 > 고르기 > 커서). 화면마다 달 필요가 없고, 사기·안 됨·크기 미리 듣기 같은 특별한 소리가 나면 저절로 겹치지 않는다.
- **묶음별 크기**: 효과음·음악 크기를 설정에서 따로. 파일마다 크기 곱(표)을 두고, 자주 나는 메뉴 소리는 작게.
- **덕킹**: 대사·창에서 음악을 약 −6dB(×0.5)로, 부드럽게 따라가게(지수 접근).
- 파일을 못 읽으면 예전 합성음으로 낸다(파일 하나 빠져도 소리가 사라지지 않게).

### 5. 사람이 할 것
- 크기 균형(음악 대 효과음), 반복이 거슬리는지, 고리 이음매, 폰 스피커·이어폰. 바꾸고 싶은 곳은 "어디 → 무엇"으로 받아 표만 고친다.

## 왜?
- CC0는 상업 배포·수정·재배포에 조건이 없어, 공개 레포에 산출물을 넣어도 된다. 라이선스가 단순하면 나중에 크레딧·고지 실수가 없다.
- 숫자로 먼저 거르는 이유: 듣는 시간은 비싸고 귀는 금방 지친다. 길이·밝기·이음매 같은 "확실히 틀린 것"은 숫자가 더 정확하다. 남은 후보만 귀로 판정하면 된다.
- 표 + 스크립트인 이유: 그림의 `.py` 원본과 같다. "어느 파일을 왜 이렇게 잘랐나"가 코드로 남고, 귀 판정 뒤의 교체가 한 줄이다.
- 메뉴 소리를 한 곳에서 내는 이유: 화면은 계속 늘어난다. 화면마다 달면 빠지는 곳이 생기고, 특별한 소리와 겹친다. "다른 소리가 났나"만 보면 둘 다 풀린다.

## 함정
- 봉우리 제한으로만 크기를 맞추면 크레스트(봉우리/RMS)가 큰 곡(피아노 타건)은 작게 남는다. 칩튠 같은 납작한 곡과 섞으면 5dB까지 차이가 난다 → 목표 RMS로 올리고 넘는 봉우리만 미리 보는 리미터로 누른다(짧은 칸마다 필요한 이득, 내려갈 때 몇 ms 미리, 올라올 때 수백 ms에 걸쳐). 누른 깊이·시간을 출력해 과하면 목표를 낮춘다. RMS는 귀의 크기(LUFS의 K 가중)와 다르니 마지막은 귀로.
- 곡 전체를 고리로 돌리면 큰 시작 화음이 고리마다 다시 터진다(조용한 끝 −21dB → 첫 화음 −7dB). 재생기가 고리 시작점을 못 받으면 고리용 판을 쓰거나 시작을 다듬는다.
- Vorbis는 풀 때 봉우리가 원래보다 커질 수 있다(+2dB). 16비트로 쓰기 전에 봉우리를 맞춘다.
- 곡의 첫 표본이 0이 아니면 처음 틀 때도, 고리마다도 딸깍한다. 앞뒤를 몇 ms 줄인다. 박자에 맞춰 만든 고리는 길이를 바꾸지 않는다(자르지 말고 줄이기만).
- mp3는 인코더가 앞뒤에 빈 표본을 붙인다. Chromium은 LAME 머리 정보로 잘라내 길이가 원본과 같았다. 다른 브라우저는 따로 확인한다.
- 메뉴 소리 훅에서 "뒤로"를 아무 데서나 내면 타이틀처럼 뒤로 갈 곳이 없는 화면에서도 소리가 난다. 그 화면은 뺀다.
- 무게중심이 아주 높은 UI 소리(Kenney open/close 12kHz)는 작은 폰 스피커에서 쉿 소리로만 들린다.
