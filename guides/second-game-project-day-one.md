# 두 번째 게임 프로젝트의 첫날

## 요약
첫 게임이 열하루 만에 v0.7까지 간 비결은 **표·경계·결정 기록·테스트가 지키는 규칙**이었고, 비쌌던 것은 그 규칙을 **늦게** 깐 자리였다(소리 핸들, 거대 틱 함수, 한 파일 글 표, 손으로 배선한 보스, 시험 없는 앱 흐름). 두 번째 프로젝트는 그것들을 첫 커밋에 깐다. 단, 뼈대가 게임보다 커지면 안 된다 — 아래 목록은 "파일 하나·함수 하나" 수준이고, 내용은 PoC가 채운다.

## 본문

### 첫 커밋에 깔 것(파일 하나씩)
| # | 무엇 | 왜(첫 게임의 근거) |
|---|---|---|
| 1 | `input.rs`: `Actions` 구조체, `KeyCode`·패드 버튼은 이 파일 밖에 없음. 눌림은 래치, 틱이 소비 | 장치가 바뀌어도(패드·터치·Android 패치) 로직은 그대로였다 |
| 2 | 고정 타임스텝 60Hz + 가변 렌더(보간), 히트스톱은 로직 시계만 | 손맛의 바탕. 나중에 바꾸면 모든 수치가 흔들린다 |
| 3 | `tuning.rs` 한 곳. 플레이어 코드에 타별 숫자를 쓰지 않는다 | 값을 찾을 수 있어야 랩·판정이 된다 |
| 4 | 로직은 부작용 핸들을 받지 않는다: 소리는 `Vec<SoundId>` 큐, 그림은 이벤트. **첫 틱부터** | 늦게 바꾸자 51곳을 옮겼다(0169 R1). 큐면 월드를 테스트에서 N틱 돌릴 수 있다 |
| 5 | `world.rs`의 틱은 **단계 메서드 목록**(`tick_player → tick_enemies → … → cleanup`). 새 메커닉은 맞는 단계에 | 1,226줄 한 함수를 자르는 데 하루 |
| 6 | 표가 될 것은 처음부터 표 + 규칙 테스트: 콤보·종·장비·시나리오·대사 | 새 적 = 표 한 줄이 되는 축이 가장 잘 굴러갔다 |
| 7 | 글은 `i18n/<언어>.rs` 언어별 파일, 키는 구조체 필드(빠지면 컴파일 에러). 처음엔 2언어(한·영)라도 **구조**는 열한 언어용 | 나중에 쪼갤 때 경로가 깨졌다. 키-필드 구조는 지켰기에 열한 언어가 됐다 |
| 8 | `scenario.rs`: 개발 시나리오 목록 + 타이틀 "개발" 메뉴(feature `dev`). 기록은 **샌드박스**(진짜 저장에 안 씀) | 같은 상황 몇 초 만에 다시. 개발 메뉴가 진짜 기록에 쓰던 결함(0269 B3) |
| 9 | 흐름(시작·쓰러짐·전환 뒤 할 일)은 순수 함수 + 시험. 앱은 실행만 | 깃발 넷이 if에 숨어 버그가 모였다(0230 R15) |
| 10 | `docs/decisions/NNNN-*.md`, 되돌리면 덧붙임. `docs/phase-*.md`에 판정 기준·구현 상태·사람이 할 일 | "그때 왜"가 바로 나왔다. 270개가 과하지 않았다 |
| 11 | CI 첫날: fmt·clippy(개발판·운영판)·test·wasm 빌드·(Android check). 운영판 = `--no-default-features` | 빨간 CI 한 번이 배포 한 번을 막는다 |
| 12 | `assets/LICENSES.md` + `assets/vendor/` gitignore. AI 생성물은 어디에 썼는지 적는다 | 공개 레포·판매 규칙(0010·0232) |
| 13 | 안내 화면 자리(`help.rs` 주제 표)와 "새 기능 = 안내 한 줄" 규칙 | 메커닉 열 개 넘으면 튜토리얼만으론 모른다 |
| 14 | 저장은 이벤트에서, 쓰기는 바뀐 때만, 슬롯 밖 설정 | 주기 저장 → 이벤트 저장으로 돌아왔다 |
| 15 | KB 경계: 프로젝트 기록은 레포, 지식은 KB. 세션 끝에 둘 다 갱신 | 검색 결과가 썩지 않는다 |

### 하지 않을 것(첫 게임이 가르친 금지)
- 마일스톤 밖의 큰 기능을 지시 없이 먼저 만들지 않는다. 마이너 버전 = 마일스톤 하나.
- 배포(main push·버전)는 사람이 정한다. "이것들을 고쳤는데 v<버전>으로 낼까요?"
- 기계 번역 초안을 그대로 쓰지 않는다. 표의 용어부터.
- PNG를 손으로 고치지 않는다(원본 + 변환 스크립트 + 재현 검사).
- 외부 JS 핫링크, 라이선스 미확인 에셋, 코드 안의 글 리터럴.

### 첫 게임에서 가져올 **코드**(복사해도 되는 것)
- `input.rs`의 래치 구조와 패드 읽기(`gamepads` 크레이트, Android 분기), 메뉴 스틱 탐색(히스테리시스).
- 고정 타임스텝 루프(`App::frame`의 누적기), 렌더 타깃 + 정수 배율.
- `prefs.rs`(웹 localStorage 정수 칸 / 네이티브 한 줄), `profile.rs`(깃발 + 수, 문자열 키).
- 웹 셸(`web/` 로딩 화면·PWA·`assemble.py`), CI 워크플로(웹·Android·iOS·PC·연기 시험), `tools/licenses.py`.
- `ui::ListView`, `ui::wrap/fit`, F3 글자 넘침 검사, 색약 점검 스크립트.
- 가져오지 않을 것: 2D 전용(`Vec2` 월드·스프라이트 시트·지형 굽기·타일 지도). 규칙·경계만 가져오고 표현은 새로.

### 첫 주의 순서(첫 게임의 단계를 다시 쓰면)
1. **스파이크**(엔진·플랫폼): 새 차원의 가장 비싼 질문 하나 — 시간 상한 있는 PoC.
2. **조작 PoC + 첫 랩**: 회색 상자, 전투감 레이어 포함(히트스톱·흔들림·넉백·소리).
3. **판정**: 사람 둘. 기준은 코드보다 먼저 적는다.
4. 그다음에야 에셋·방·보스·이야기.

## 왜?
규칙은 코드가 적을 때 공짜고 많을 때 하루씩이다. 첫 게임의 리팩터링 기록(0169·0170·0230·0248)은 전부 "규칙을 늦게 깐 값"이고, 그 값을 아는 지금 두 번째 게임에서 다시 내지 않는 게 이 노트의 목적이다. 반대로 규칙이 게임보다 먼저 커지는 것도 실패다 — 그래서 목록은 "파일 하나·함수 하나"에서 멈춘다.

## 함정
- 첫 게임의 코드를 통째로 복사하면 2D 가정(정수 픽셀·y 정렬·타일)이 따라온다. 경계만.
- "열한 언어 구조"를 첫날에 깐다는 건 파일 열한 개가 아니라 **키 = 구조체 필드** 규칙 하나다.
- 결정 기록이 코드보다 늦으면 "왜"가 사라진다. 결정 → 코드 → 기록 갱신 순서.
