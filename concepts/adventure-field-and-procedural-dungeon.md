# 탑다운 모험 구조

## 요약
JRPG식 "필드에서 걷다가 던전에 들어간다"를 1인 개발 규모로 만들 때, **월드를 격자 하나**로 두고 **카메라에 머무는 사각형(경계)** 하나만 주면 필드의 연속 스크롤과 던전의 방 단위 밀기 전환이 같은 코드에서 나온다. 던전은 칸 위에 방을 붙이는 **방 그래프**로 생성하고, 방의 역할(보스·보물·휴식)은 시작방에서의 거리로 정한다.

## 본문
- **격자 하나**: 필드(손으로 그린 ASCII)와 던전(생성기가 채움)을 같은 `Grid`(칸 종류: 바닥·벽·문·입구·출구·저장)로. 충돌은 벽 칸을 가로로 이어 붙인 사각형 몇십 개 + 소품. 원 vs 사각형 하나로 충분하다.
- **카메라 = 경계 안 추적**: 목표 = 플레이어 위치를 경계 사각형 안으로 clamp. 카메라는 목표로 지수 감쇠(`cam += (target-cam)·(1-e^{-k·dt})`). 경계가 필드 전체면 연속 스크롤, 던전에서 "지금 방"이면 방 밖이 안 보이고, 방을 넘는 순간 경계가 바뀌어 **저절로 미끄러진다**. 따로 트윈을 둘 필요가 없다.
- **방 그래프 던전**: N×N 칸 → 시작방에서 무작위로 가지를 뻗고 고리 하나 추가. 너비 우선 거리로 가장 먼 방 = 보스, 막다른 방 = 보물·휴식. 이웃 방 사이 벽 가운데에 문.
- **방 잠금**: 문 칸에서 한두 칸 안쪽(방 내부)에 들어섰을 때 잠그고 적을 깨운다(짧은 지연). 다 잡으면 연다. 잠긴 문은 충돌 사각형을 다시 만들어 벽처럼.
- **필드 적**: 자다가 일정 거리 안에 오거나 맞으면 깬다. 화면 밖 적이 몰려오지 않는다.
- **장소 바꾸기**: 페이드 아웃(로직 정지) → 장소 교체 → 페이드 인. 던전에 있는 동안 필드 상태(적·바닥 물건)를 맡겨 두고 돌아올 때 복원.
- **죽음 = 저장 지점에서 다시**: 성장(장신구·영구 체력)은 남기고 화폐 일부만 잃게 하면 "다시 해 볼까"가 가볍다.

## 왜?
- 화면 방 전환은 **경계가 바뀌는 것**이고, 연속 스크롤은 **경계가 큰 것**일 뿐이다. 둘을 같은 식으로 보면 카메라 코드가 한 곳이 된다. Zelda식 구현들이 "경계 갱신 + 카메라 이동"을 따로 트윈하다가 카메라가 튀는 버그를 겪는 것도 둘이 따로 놀기 때문이다. 하나의 추적 식에 경계만 넣으면 그런 어긋남이 없다.
- 보스를 "가장 먼 곳"에 두면 탐색 동선이 저절로 생긴다(Isaac도 가장 먼 막다른 방에 보스). 거리만 쓰면 생성 규칙이 짧고 테스트하기 쉽다(연결성·보스 하나·같은 시드 = 같은 결과).
- 방을 화면 크기로 두면 "방 하나 = 전투 하나"라 난이도 단위가 분명하고, 잠금이 도망치기·적 끌고 다니기를 막는다.

## 함정
- **출구·입구 칸을 동선 위에 두지 말 것**: 시작방 한가운데 출구를 두었더니 위쪽 문으로 가다 밟아서 던전을 나가 버렸다. 구석으로.
- **문 바로 위에서 잠그면 갇힘 판정이 애매**: 문 칸에서 안쪽으로 들어선 뒤 잠근다.
- 밀기 전환 중에도 로직이 돈다(우리 방식). 적이 전환 중에 공격하면 불공평하므로 방 적에 깨어나는 지연(0.7초쯤)을 준다. Zelda식으로 전환 동안 입력·로직을 멈추는 것도 방법.
- 월드 좌표가 화면보다 커지므로 화면 고정 요소(HUD, 튜토리얼 화살표)는 카메라 기준으로 다시 계산해야 한다.
