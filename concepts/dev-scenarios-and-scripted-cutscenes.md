# 개발용 시나리오 진입점과 스텝 스크립트 컷씬

## 요약
손맛 조정과 판정은 "같은 상황을 몇 초 안에 다시 만드는" 비용이 정한다. 월드 구성을 `시나리오` 목록(이름·설명·구성 함수)으로 두고 타이틀의 개발 메뉴에서 바로 들어가게 하면, 상황 하나 추가가 한 줄이 된다. 컷씬은 영상이 아니라 **스텝 목록**(대화·이동·대기·등장·페이드)을 월드 위에서 재생하는 JRPG 방식이 에셋 없이도 되고 건너뛰기가 쉽다.

## 본문

### 시나리오 진입점
- `enum Scenario`와 `LIST: [Entry]`(이름·설명·시나리오). `build(scenario) -> World`가 월드를 만든다. 월드에는 `empty()`, `spawn_enemy()`, `auto_waves` 같은 **구성용 API**가 있어야 한다. 게임 로직이 "기본 시작"만 알면 테스트 진입점이 생길 수 없다.
- "다시 시작"은 **현재 시나리오**를 다시 만든다. 기본 시작으로 되돌아가면 테스트 루프가 끊긴다.
- cargo feature(`dev`, 기본 켬)로 타이틀 항목을 가린다. 배포 빌드는 `--no-default-features`. 프로토타입 단계에서는 배포본에도 켜 두는 편이 테스터에게 유리하다.
- 시나리오 설명에 **그 시나리오가 검증하는 판정 기준**을 적어 두면(예: "판정 2: 위치 선정"), 테스트가 목적을 잃지 않는다.

### 스텝 스크립트 컷씬
- `Step`: `Say{actor,text}`, `Move{actor,to,speed}`, `Face`, `Wait(s)`, `Show/Hide`, `Fade{to_clear,secs}`, `Shake`. 한 번에 하나씩 순서대로.
- 배우 0번은 플레이어다. 컷씬이 플레이어의 월드 위치를 직접 움직여야 컷씬 끝의 위치가 게임으로 이어진다. 다른 배우는 컷씬이 소유한 임시 객체.
- 대화창: 아래 전체 폭, 이름표, 초상 자리(그림이 없으면 배우 색 네모), 타자 효과(초당 40자 정도), 다 찍히면 ▼ 깜빡임. 확인은 "다 찍히기 전이면 전부 보여 주기, 다 찍혔으면 다음".
- **건너뛰기**(뒤로 키)는 처음부터. 남은 스텝 중 이동·등장·퇴장·페이드는 즉시 최종 상태로 적용하고 끝낸다. 그래야 건너뛴 뒤의 월드가 정상 재생과 같다.
- 컷씬 중 월드 로직은 멈추고(틱 없음) 렌더만 한다. 보간 prev를 현재로 맞춰 떨림을 막는다([fixed-timestep-and-hitstop.md](fixed-timestep-and-hitstop.md)).

### 일러스트 장면(한 장 그림 + 내레이션)
감정의 정점은 작은 스프라이트로 못 보여 준다. 스텝 둘을 더하면 같은 스크립트 안에서 "CG"를 쓸 수 있다.
- `Illust(Option<그림>)`: 화면 전체를 덮는 그림을 띄우거나 내린다.
- `Narrate(글)`: 이름표·초상화 없이 아래쪽 가운데 맞춤. 뒤는 **네모 띠가 아니라 화면 아래에서 위로 옅어지는 어둠**(양옆·위 모서리 없음) + 글 테두리. 네모 띠는 그림 위에 뜬 UI 상자처럼 "미묘하게 거슬렸다"(사람 피드백, 2026-10-27).
- 장면 바꾸기는 "어두워짐 → 그림 바꿈 → 밝아짐" 세 스텝 묶음으로 한다. 대사는 그림 위에 늘 쓰던 대화창으로 뜬다.

그림 사양:
- **크기**: 게임 화면의 2배 밀도(320×180 게임이면 640×360). 초상화와 같은 셈법이고 도트 결을 지킨다.
- **패닝**: 그림을 창보다 크게 그려 두고 부드럽게 출발·멈춤, 정수 원본 px 단위로 움직인다.
- **입자**: 꽃잎·포자 같은 것은 상태 없이 시간만으로 위치를 정한다(해시 + sin). 건너뛰기·다시 보기에도 같고 테스트하기 쉽다.
- **안전 영역**: 대화창이 아래 1/3을 덮으니 중요한 것은 위 2/3에 둔다. 사람에게 그림을 맡길 때 사양서에 숫자로 적는다.

## 왜?
- 1인 개발에서 가장 비싼 것은 "확인하러 가는 시간"이다. 진입점이 없으면 조정 한 번에 1분씩 들고, 그 1분이 조정 횟수를 10분의 1로 줄인다.
- JRPG식 컷씬은 그림이 없어도 성립하고, 2방향 스프라이트·3/4 뷰와 맞으며, 스크립트가 코드든 데이터든 같은 구조다. 영상·일러스트 컷씬은 콘텐츠 비용을 폭발시킨다.

## 함정
- 대화 텍스트의 줄바꿈은 창 폭과 폰트에 묶인다. 세 줄을 넘는 대사는 스텝을 둘로 나눈다(자동 페이지 넘김은 나중에).
- 컷씬이 플레이어 위치를 바꾸므로 끝난 뒤 적 스폰 위치가 플레이어와 겹치지 않게 스폰 지점은 플레이어 거리로 거른다.
- **배우를 그리는 좌표계**: 월드 패스가 끝나고 카메라를 화면 고정(HUD)으로 바꾼 뒤에 컷씬 배우를 월드 좌표로 그리면, 카메라가 (0, 0)인 첫 화면에서만 맞는다. 첫 컷씬(오프닝)이 거기라 숨어 있다가 지도 다른 곳의 컷씬에서 배우가 화면 밖으로 나간다. 배우는 월드 패스 안에서 그리거나, "이번 프레임 화면 왼쪽 위(흔들림 포함)"를 빼서 화면 좌표로 그린다.
- **싸움 끝 연타**: 보스를 잡는 순간까지 공격을 연타하면, 공격 = 대사 넘기기라서 처치 컷씬 대사를 다 넘긴다. 컷씬 시작 후 ~1초, 줄마다 ~0.3초는 확인을 버린다(사망 화면의 입력 잠금과 같은 생각).
- 카메라가 주인공을 따라가면 멀리 선 배우는 아래 대화창 뒤에 가려진다. 말하기 전에 배우를 주인공 곁으로 걸어오게 한다.
- **조명(어둠 + 빛 한 점) 스텝은 빛의 자리도 보간한다**: 진하기만 보간하고 자리는 스텝 첫 틱에 새 배우로 옮기면, 진하기가 같은 "빛만 옮기기" 스텝은 순간이동이 되어 어색하다(사람 판정). 스텝을 시작할 때의 빛 자리·크기에서 새 자리로 처음·끝이 느린 곡선(smoothstep)으로 옮기면 빛이 주인공에서 상대에게 건너가며 시선을 데려간다. 어둠이 아직 없으면 미끄러져 올 자리가 없으니 처음부터 그 자리에(nail 0190).
- 키 입력 "눌림"을 프레임당 한 번만 세면 같은 프레임에 두 번 누른 입력은 하나로 합쳐진다. 사람 손은 괜찮지만 자동화 테스트는 키 사이에 100ms 이상 띄워야 한다.

- **홀수 화면 배율과 2배 밀도 그림**: 화면 배율 3이면 원본 1px = 1.5 화면 px라 고르지 않다.
  - 짝수로 줄이면(예전 초상화 방식, nail 0015) 화면의 2/3로 작아진다. nail 초상화는 0111부터 꽉 채우고 점이 2·3px 번갈아 찍히는 것을 받아들였다. 꽉 채우려면 고르지 않음을 받아들이고, 그림에서 1px 디더·체크 무늬를 빼서 얼룩을 줄인다.
- **번역기가 짧은 이야기 문장을 엉뚱하게 읽는다**: 문맥 없이 줄 단위로 넘기면 이런 일이 생긴다(실제로 걸림). 줄마다 사람이 고친다.
  - "보라 실이"를 "Behold"로 옮겼다.
  - "실은 물러났지만"의 "실은"을 "사실은"으로 읽었다.
  - "모모야."(내 이름은 모모야)를 이름 "Momoya"로 옮겼다.
  - "오늘부터 네 굴을 찾아"의 주어를 뒤집었다.
